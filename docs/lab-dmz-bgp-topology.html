Lab topology: inside, DMZ and outside with eBGP

SJB-OS (AS 65244) peers with the upstream router (AS 65534) on outside and announces only the DMZ. Inside stays private behind an outbound allow-list and leaves NATed; the DMZ's web server is routed by its real address. Config: examples/lab-dmz-bgp.yaml; tests: tools/lab-test.sh.

IPS is the enterprise profile: critical and major blocked, minor alerted. NAT: inside-out masquerades inside leaving on outside; the DMZ is not NATed.

TLS decryption

  • Inside's web to outside is decrypted with the enterprise profile: bad certificates blocked, pinned apps excluded.
  • Never decrypted: hosts tagged no-decrypt, anything on the home LAN, and the exclusion lists (OS updates and sign-in, collaboration, pinned apps, GitHub raw, the SJB site).
  • The DMZ is never decrypted, in either direction.

Testing

Copy lab-test.sh to each machine and run it with its role. Every check has a working control beside it, so a failure is evidence and an unreachable lab shows as skipped, not passed.

Run onCommandWhat it checks
inside client./lab-test.sh -r insideDHCP lease, the firewall closed but pingable, the DMZ web page, then the whole outbound policy: web, approved DNS, NTP, mail, ping, the allow-list, risky apps, IPS, decryption. Prints its address for -c.
DMZ web server./lab-test.sh -r dmz -c CLIENTIts address and gateway, its own web page, the firewall, inside out of reach, outbound open and not decrypted.
home LAN or wifi./lab-test.sh -r outside -c CLIENTWeb to the DMZ allowed and inspected (test signatures), every other port to the DMZ dropped, inside out of reach, the firewall's outside address closed.

The DMZ web server is 192.168.151.10, the script's default. Afterwards: show log traffic, show log threat, show log decryption.
